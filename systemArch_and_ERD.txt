################################################################################
# 1. SYSTEM ARCHITECTURE (3-TIER CLIENT-SERVER)
################################################################################

Use this section to redraw Figure 4.1 ("System Architecture of ParkiPay") as
a layered / component / deployment diagram.

--------------------------------------------------------------------------------
1.1  Layers and components
--------------------------------------------------------------------------------

LAYER 1 -- PRESENTATION TIER (Mobile Client)
    Component:  ParkiPay Mobile App
    Technology: React Native (Expo) + TypeScript, Expo Router
    Screens:
        - (auth)/login.tsx              Officer login (employee ID)
        - (app)/home.tsx                Dashboard / landing screen
        - (app)/lookup.tsx              Vehicle plate lookup + OCR + billing
        - (app)/history.tsx             Officer's billing history & stats
        - (app)/alerts.tsx              Bill-expiry / system alerts
        - (app)/vehicles.tsx            Vehicle registry (view/register/remove)
        - (app)/admin.tsx               Supervisor-only: officers & locations
    State/services:
        - store/authStore.ts            Session/auth state (Zustand-style store)
        - store/settingsStore.ts        App settings state
        - services/api.ts               Central HTTP client (adds Bearer token)
        - services/alertsService.ts     Alerts logic
        - hooks/useAuth.ts              Auth/session hook
        - hooks/useBiometric.ts         Biometric login hook
    Communicates over:  HTTPS (JSON) --> Application Tier only

LAYER 2 -- APPLICATION TIER (Backend REST API)
    Component:  ParkiPay API
    Technology: Node.js + Express
    Routes (Express routers):
        - src/routes/auth.js        /api/auth/*        Login, refresh, logout, me
        - src/routes/vehicles.js    /api/vehicles/*     Lookup, locations, OCR
        - src/routes/billing.js     /api/billing/*      Generate/history/stats
        - src/routes/admin.js       /api/admin/*        Officers/locations/vehicles
        - src/routes/health.js      /api/health/        Liveness probe
    Cross-cutting middleware:
        - middleware/auth.js        JWT verification + officer/role attach
        - middleware/errorHandler.js Centralised error responses
    Core libraries:
        - lib/jwt.js                Sign/verify/blacklist JSON Web Tokens
        - lib/prisma.js             Prisma Client singleton (DB access)
        - lib/redis.js              Redis client + cacheGet/cacheSet/cacheDel
        - lib/controlNumber.js      Control-number generation + active-bill check
        - lib/sms.js                Twilio SMS dispatch
        - lib/audit.js              Audit-log writer
    Communicates with:
        - PostgreSQL (via Prisma ORM)         -- persistent data
        - Redis                                -- cache (vehicle/bill/stats)
        - Twilio API                           -- outbound SMS
        - Tesseract.js (in-process OCR engine) -- plate text extraction

LAYER 3 -- DATA TIER
    - PostgreSQL 15+ (hosted on Supabase)  -- system of record
    - Redis (hosted on Upstash, TLS)       -- cache, short TTL (60s-600s)

EXTERNAL SERVICES (consumed by Application Tier only)
    - Twilio            -- SMS delivery of bill notifications to vehicle owners
    - Tesseract.js OCR  -- image-to-text plate recognition
    - Resend (optional) -- transactional email (per project stack notes)

--------------------------------------------------------------------------------
1.2  ASCII layout (redraw as boxes + arrows in your diagramming tool)
--------------------------------------------------------------------------------

    +-------------------------------------------------------------+
    |                     PRESENTATION TIER                       |
    |   ParkiPay Mobile App (React Native / Expo / TypeScript)    |
    |   Screens: Login | Home | Lookup&Bill | History | Alerts |  |
    |            Vehicles | Admin (Supervisor only)               |
    +---------------------------+-----------------------------------+
                                | HTTPS (JSON, Bearer JWT)
                                v
    +-------------------------------------------------------------+
    |                     APPLICATION TIER                        |
    |         ParkiPay REST API  (Node.js + Express)               |
    |  /api/auth  /api/vehicles  /api/billing  /api/admin  /health |
    |  Middleware: JWT auth (role: ATTENDANT | SUPERVISOR)         |
    |  Business logic: fee calc, duplicate-bill cooldown, audit    |
    +------+----------------+------------------+-------------------+
           |                |                  |
           v                v                  v
    +-------------+  +-------------+   +----------------------+
    | PostgreSQL  |  |   Redis     |   |  External Services   |
    | (Supabase)  |  |  (Upstash)  |   |  - Twilio (SMS)       |
    | via Prisma  |  |  cache      |   |  - Tesseract.js (OCR) |
    |    ORM      |  |             |   |  - Resend (email)     |
    +-------------+  +-------------+   +----------------------+

Deployment note: only the Application Tier is permitted to talk to the Data
Tier and External Services; the Mobile Client never calls the database,
cache, Twilio or the OCR engine directly. This enforces that all billing
rules (fee calculation, duplicate-bill prevention, audit logging) execute
in one trusted place and cannot be bypassed from a compromised or modified
mobile client.

# 2. USE CASE DIAGRAM -- ACTORS AND USE CASES
################################################################################

Use this section to redraw Figure 4.3 ("Use Case Diagram for ParkiPay").

ACTORS
    - Attendant   (OfficerRole = ATTENDANT)
    - Supervisor  (OfficerRole = SUPERVISOR)   [inherits all Attendant use cases]

USE CASES (Attendant)
    - Login (with Employee ID)
    - Login with Biometric (shortcut, after first login)
    - Look Up Vehicle by Plate
    - Scan Plate (OCR capture via camera)
    - Generate Parking Bill
    - View Active Bill for a Plate
    - View Own Billing History
    - View Own Billing Statistics
    - View Alerts (e.g. bills nearing expiry)
    - View Vehicle Registry
    - Logout

USE CASES (Supervisor only -- extends Attendant)
    - Manage Officers (create / list / remove / reassign location)
    - Manage Parking Locations (list active locations)
    - Manage Vehicle Registry (register new vehicle / remove vehicle)

SYSTEM BOUNDARY: "ParkiPay Mobile-Based Parking Fee Billing and Management System"

# 3. ENTITY RELATIONSHIP DIAGRAM (ERD)
################################################################################

Use this section to redraw Figure 4.2 ("Entity Relationship Diagram of the
ParkiPay Database"). Section 3.1 gives a human-readable relationship summary;
Section 4 gives the raw Prisma schema (import-ready / copy-paste-ready into
Prisma-aware ERD tools, e.g. https://prisma-erd.simonknott.de or
dbdiagram.io via a DBML converter).

--------------------------------------------------------------------------------
3.1  Entities, primary keys and cardinalities
--------------------------------------------------------------------------------

ENTITY: Officer
    PK: id (int, autoincrement)
    Unique: employeeId
    Attributes: fullName, phone, email, role (enum), passwordHash,
                locationId (FK, nullable), isActive, failedLoginAttempts,
                lockedUntil, lastLogin, createdAt, updatedAt

ENTITY: ParkingLocation
    PK: id (int, autoincrement)
    Attributes: name, region, district, address, latitude, longitude,
                feeMotorcycle, feePrivateCar, feeMinibus, feeBus, feeTruck,
                feeGovernment, isActive, createdAt, updatedAt

ENTITY: Vehicle
    PK: id (int, autoincrement)
    Unique: plateNumber
    Attributes: ownerName, ownerPhone, ownerEmail, make, model, color, year,
                category (enum), registrationDate, isValid, createdAt, updatedAt

ENTITY: ControlNumber   (the digital "Bill")
    PK: id (int, autoincrement)
    Unique: controlNumber
    Attributes: plateNumber, vehicleId (FK, nullable), officerId (FK, nullable),
                locationId (FK, nullable), amountDue, generatedAt, expiresAt,
                status (enum), smsSent, emailSent, smsError, notes, createdAt

ENTITY: AuditLog
    PK: id (int, autoincrement)
    Attributes: officerId (FK, nullable), action, plateNumber, controlNumber,
                result, ipAddress, userAgent, extra (JSON), timestamp

ENTITY: OfficerBiometric
    PK: id (int, autoincrement)
    Unique: officerId (FK, one-to-one), token
    Attributes: deviceHint, isActive, createdAt, updatedAt

ENTITY: BlacklistedToken
    PK: id (int, autoincrement)
    Unique: jti
    Attributes: expiresAt, createdAt

RELATIONSHIPS (cardinality)
    ParkingLocation  (1) ----< (many)  Officer            "employs / staffs"
    ParkingLocation  (1) ----< (many)  ControlNumber      "hosts bills"
    Officer          (1) ----< (many)  ControlNumber      "issues"
    Officer          (1) ----< (many)  AuditLog           "performs"
    Officer          (1) ----  (0..1)  OfficerBiometric   "has"
    Vehicle          (1) ----< (many)  ControlNumber      "is billed against"
    BlacklistedToken  -- standalone (no FK relationships)

--------------------------------------------------------------------------------
3.2  Text-based ER diagram (crow's-foot style, redraw in your ERD tool)
--------------------------------------------------------------------------------

  ParkingLocation ||--o{ Officer            : "assigned to"
  ParkingLocation ||--o{ ControlNumber      : "billed at"
  Officer         ||--o{ ControlNumber      : "issues"
  Officer         ||--o{ AuditLog           : "performs"
  Officer         ||--o| OfficerBiometric   : "has"
  Vehicle         ||--o{ ControlNumber      : "billed against"

  (||  = exactly one,  o{ = zero-or-many,  o| = zero-or-one)

# 4. RAW PRISMA SCHEMA (single source of truth for the ERD above)
################################################################################
# This is the actual data-model file from the ParkiPay project
# (backend/prisma/schema.prisma). Paste it directly into any tool that
# accepts Prisma schema syntax to auto-generate a formal ERD.
################################################################################

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")
  directUrl = env("DIRECT_URL")
}

model Officer {
  id                  Int               @id @default(autoincrement())
  employeeId          String            @unique @map("employee_id")
  fullName            String            @map("full_name")
  phone               String            @default("")
  email               String            @default("")
  role                OfficerRole       @default(ATTENDANT)
  passwordHash        String            @map("password_hash")
  locationId          Int?              @map("location_id")
  isActive            Boolean           @default(true) @map("is_active")
  failedLoginAttempts Int               @default(0) @map("failed_login_attempts")
  lockedUntil         DateTime?         @map("locked_until")
  lastLogin           DateTime?         @map("last_login")
  createdAt           DateTime          @default(now()) @map("created_at")
  updatedAt           DateTime          @updatedAt @map("updated_at")
  auditLogs           AuditLog[]
  bills               ControlNumber[]
  biometric           OfficerBiometric?
  location            ParkingLocation?  @relation(fields: [locationId], references: [id])

  @@map("officers")
}

model AuditLog {
  id            Int      @id @default(autoincrement())
  officerId     Int?     @map("officer_id")
  action        String
  plateNumber   String   @default("") @map("plate_number")
  controlNumber String   @default("") @map("control_number")
  result        String   @default("")
  ipAddress     String?  @map("ip_address")
  userAgent     String   @default("") @map("user_agent")
  extra         Json     @default("{}")
  timestamp     DateTime @default(now())
  officer       Officer? @relation(fields: [officerId], references: [id])

  @@index([action, timestamp])
  @@index([officerId, timestamp])
  @@map("audit_logs")
}

model ParkingLocation {
  id             Int             @id @default(autoincrement())
  name           String
  region         String
  district       String          @default("")
  address        String          @default("")
  latitude       Decimal?        @db.Decimal(10, 7)
  longitude      Decimal?        @db.Decimal(10, 7)
  feeMotorcycle  Decimal         @default(500) @map("fee_motorcycle") @db.Decimal(10, 2)
  feePrivateCar  Decimal         @default(1000) @map("fee_private_car") @db.Decimal(10, 2)
  feeMinibus     Decimal         @default(2000) @map("fee_minibus") @db.Decimal(10, 2)
  feeBus         Decimal         @default(3000) @map("fee_bus") @db.Decimal(10, 2)
  feeTruck       Decimal         @default(5000) @map("fee_truck") @db.Decimal(10, 2)
  feeGovernment  Decimal         @default(0) @map("fee_government") @db.Decimal(10, 2)
  isActive       Boolean         @default(true) @map("is_active")
  createdAt      DateTime        @default(now()) @map("created_at")
  updatedAt      DateTime        @updatedAt @map("updated_at")
  controlNumbers ControlNumber[]
  officers       Officer[]

  @@map("parking_locations")
}

model Vehicle {
  id               Int             @id @default(autoincrement())
  plateNumber      String          @unique @map("plate_number")
  ownerName        String          @map("owner_name")
  ownerPhone       String          @map("owner_phone")
  ownerEmail       String          @default("") @map("owner_email")
  make             String          @default("")
  model            String          @default("")
  color            String          @default("")
  year             Int?
  category         VehicleCategory @default(PRIVATE_CAR)
  registrationDate DateTime?       @map("registration_date")
  isValid          Boolean         @default(true) @map("is_valid")
  createdAt        DateTime        @default(now()) @map("created_at")
  updatedAt        DateTime        @updatedAt @map("updated_at")
  controlNumbers   ControlNumber[]

  @@map("vehicles")
}

model ControlNumber {
  id            Int              @id @default(autoincrement())
  controlNumber String           @unique @map("control_number")
  plateNumber   String           @map("plate_number")
  vehicleId     Int?             @map("vehicle_id")
  officerId     Int?             @map("officer_id")
  locationId    Int?             @map("location_id")
  amountDue     Decimal          @map("amount_due") @db.Decimal(10, 2)
  generatedAt   DateTime         @default(now()) @map("generated_at")
  expiresAt     DateTime         @map("expires_at")
  status        BillStatus       @default(ACTIVE)
  smsSent       Boolean          @default(false) @map("sms_sent")
  emailSent     Boolean          @default(false) @map("email_sent")
  smsError      String           @default("") @map("sms_error")
  notes         String           @default("")
  createdAt     DateTime         @default(now()) @map("created_at")
  location      ParkingLocation? @relation(fields: [locationId], references: [id])
  officer       Officer?         @relation(fields: [officerId], references: [id])
  vehicle       Vehicle?         @relation(fields: [vehicleId], references: [id])

  @@index([officerId, generatedAt])
  @@index([plateNumber, status, expiresAt])
  @@index([status, expiresAt])
  @@map("control_numbers")
}

model BlacklistedToken {
  id        Int      @id @default(autoincrement())
  jti       String   @unique
  expiresAt DateTime @map("expires_at")
  createdAt DateTime @default(now()) @map("created_at")

  @@map("blacklisted_tokens")
}

model OfficerBiometric {
  id         Int      @id @default(autoincrement())
  officerId  Int      @unique @map("officer_id")
  token      String   @unique @db.VarChar(128)
  deviceHint String   @default("device") @map("device_hint") @db.VarChar(64)
  isActive   Boolean  @default(true) @map("is_active")
  createdAt  DateTime @default(now()) @map("created_at") @db.Timestamptz(6)
  updatedAt  DateTime @default(now()) @updatedAt @map("updated_at") @db.Timestamptz(6)
  officer    Officer  @relation(fields: [officerId], references: [id], onDelete: Cascade, onUpdate: NoAction)

  @@map("officer_biometrics")
}

enum BillStatus {
  ACTIVE
  EXPIRED
  PAID
}

enum OfficerRole {
  ATTENDANT
  SUPERVISOR
}

enum VehicleCategory {
  MOTORCYCLE
  PRIVATE_CAR
  MINIBUS
  BUS
  TRUCK
  GOVERNMENT
}

# 5. HOW TO TURN THIS INTO A DRAWN UML DIAGRAM
################################################################################

Option A -- Manual redraw (recommended for a dissertation figure):
    1. Open draw.io (https://app.diagrams.net) or Lucidchart.
    2. For the ARCHITECTURE diagram: create 3 horizontal swim-lanes
       (Presentation / Application / Data + External Services) using the
       boxes and arrows listed in Section 1.2.
    3. For the ERD: use the "Entity Relation" shape library; create one
       rectangle per entity in Section 3.1, list its attributes, and connect
       entities using crow's-foot connectors per Section 3.2.
    4. For the USE CASE diagram: use the UML "Use Case" shape library; place
       the Attendant and Supervisor actors on the left, the system boundary
       box in the centre with ovals per use case from Section 2, and let
       Supervisor's association lines include all Attendant use cases plus
       the three supervisor-only ones.

Option B -- Automatic ERD generation from the Prisma schema:
    1. Save Section 4 above as "schema.prisma".
    2. Use an online Prisma ERD renderer (e.g. https://prisma-erd.simonknott.de)
       or the npm package "prisma-erd-generator" to auto-generate an ERD
       image, which can then be imported into draw.io/Lucidchart for final
       styling to match the rest of the dissertation's figures.

Option C -- dbdiagram.io:
    1. Convert the Prisma schema in Section 4 to DBML (Database Markup
       Language) -- either manually or with a Prisma-to-DBML converter.
    2. Paste the DBML into https://dbdiagram.io to get an interactive,
       exportable ERD (PNG/PDF/SVG).
